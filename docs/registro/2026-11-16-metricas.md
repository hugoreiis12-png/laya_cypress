# Métricas do serviço (`GET /metrics`) — 2026-11-16

O `laya-cypress` expõe métricas no formato Prometheus em `GET /metrics`, na mesma porta 8020.

- **Desligado por padrão.** O endpoint só existe com `METRICS_API_KEY` definida; sem ela, responde 404.
- **Token próprio.** O scraper usa `Authorization: Bearer <METRICS_API_KEY>`. O `API_KEY` da API não abre as métricas, e o token das métricas não abre a API.
- **Só contagens.** Os rótulos são tipo, estado, motor, motivo, versão e resultado. Nunca id, telefone, CNPJ, texto ou imagem.
- **Contadores em memória.** Zeram quando o container reinicia; use `rate()` ou `increase()`.

## Ativar
1. `requirements.txt` da raiz: `prometheus_client==0.21.1`.
2. `compose.yaml` da raiz, `environment` do `laya-cypress`: `METRICS_API_KEY: ${METRICS_API_KEY:-}`.
3. Gere o token (`openssl rand -hex 32`), defina `METRICS_API_KEY` na stack do serviço no Portainer e faça o redeploy.
4. Teste na VM:
   ```bash
   curl -s -H "Authorization: Bearer <token>" http://192.168.0.160:8020/metrics | grep '^laya_' | head
   ```

## Scrape (VictoriaMetrics + Grafana)
O VictoriaMetrics (single com `-promscrape.config`, ou `vmagent`) lê o mesmo formato de configuração do Prometheus. No Grafana, a fonte de dados é do tipo **Prometheus** apontando para o VictoriaMetrics (`http://<vm>:8428`); as consultas abaixo valem como MetricsQL.
```yaml
scrape_configs:
- job_name: laya-cypress
  metrics_path: /metrics
  authorization:
    type: Bearer
    credentials_file: /etc/prometheus/laya_metrics_token
  static_configs:
    - targets: ["192.168.0.160:8020"]   # ou 100.66.232.113:8020 pelo Tailscale
```

## Métricas
| Métrica | Rótulos | O que mede |
|---|---|---|
| `laya_decisoes_total` | `tipo`, `estado_assinatura`, `motor_assinatura` (`juiz`, `laya_visao`, `outro`), `inconclusivo` | Decisões |
| `laya_inconclusivos_total` | `motivo` | Por que a foto foi ao Gemini |
| `laya_decisao_latencia_segundos` | (histograma) | Tempo de cada decisão |
| `laya_falhas_motor_total` | `motor` | Falhas de OCR, juiz, Laya etc. |
| `laya_capacidade_juiz_total` | `resultado` | Admissão no vLLM (`ok` ou motivo da recusa) |
| `laya_segunda_olhada_total` | `resultado` (`true`, `false`, `desconhecido`) | Segunda olhada do juiz |
| `laya_fila_cheia_total` | — | Pedidos recusados com 503 |
| `laya_visao_observacoes_total` | `versao`, `rotulo`, `pronta` | Opiniões da Laya visão |
| `laya_visao_concordancia_total` | `versao`, `concorda` | Laya visão × voto do juiz, quando os dois opinam |
| `laya_visao_assumiu_total` | `versao` | Canhotos liberados pela Laya sem o juiz |
| `laya_visao_erros_total` | `erro` | Sem opinião (`sem_registro`, `sem_versao`, …) |
| `laya_referencias_total` | `origem` (`gemini`, `vllm`) | Referências gravadas; `vllm` é a análise completa que deu certo |
| `laya_analise_completa_total` | `resultado` (`descartada_fila_cheia`, `descartada_vllm_ocupado`, `falhou`) | Análises completas que não viraram referência |
| `laya_analise_completa_fila` | — | Fotos esperando o vLLM ocioso |
| `laya_caixa_trainer_total` | `resultado` | Fotos deixadas para o trainer |

## Consultas úteis
```promql
# concordância da Laya visão com o juiz nas últimas 24 h (critério para ligar LAYA_VISION_TAKEOVER)
sum by (versao) (increase(laya_visao_concordancia_total{concorda="sim"}[24h]))
  / sum by (versao) (increase(laya_visao_concordancia_total[24h]))

# fração de canhotos que caem no Gemini
sum(rate(laya_decisoes_total{tipo="canhoto",inconclusivo="true"}[1h])) / sum(rate(laya_decisoes_total{tipo="canhoto"}[1h]))

# p95 de latência
histogram_quantile(0.95, sum by (le) (rate(laya_decisao_latencia_segundos_bucket[15m])))
```
